## 一、现状盘点

### 1.1 核心结论

仓库当前**没有任何断言/契约设施**（在 layers/ 与 core/ 全部 py 文件中 grep `assertion|contract|断言|claim` 零命中）。最接近的概念是 `core/brain.py` 的 `SubTask.acceptance: str`（自由文本验收标准），但 Inspect 层**并未真正消费它**——Checker 规则全是手工预设的。所以 M1 是全新建，不是改造；M2 是把 repair 层的"文本匹配"替换为"类型驱动"；M3 是全新建。

好消息是：**6 种验证原语恰好就是断言谓词的编译目标**，`FixPlan`/`ReAssembler` 恰好是修复动作的执行端，`EventBus`（含 `replay()`）恰好是升级/降级审计轨迹的落点。改造量可控。

## 四、风险点（哪些改动可能破坏现有 39 个测试文件）

| # | 风险 | 影响 | 对策 |
|---|---|---|---|

## 五、分步计划（每步可独立验证）

> 顺序即任务包 T1.1 → T1.5。每步：写码 → 补单测 → 跑验收 → git commit（中文 message）→ 下一步。
> 通用验收前置：`pytest tests/unit/ -x -q`（保证存量 32 个 unit 测试不红）。

### 步骤 1 · T1.1 断言契约层（M1 主体）

1. 建 `layers/contract/` 包：`assertion.py`（pydantic v2 模型：`aid/kind[pre|post|invariant]/subject/predicate/level[0-3]/producer/origin[llm|human|learned]/status[unverified|verified|falsified]`）。
2. `compiler.py`：输入候选断言（自然语言 + 结构化提示），输出映射到 6 原语之一的 `Assertion`，编不过丢弃并计数；对外暴露 `compile_rate` 统计。
3. `ledger.py`：节点 = 断言；边 = `derive/depends_on/invalidates/trigger`；`falsify(aid)` 只置状态 + 记 `invalidates` 边，**不抛异常不打断执行流**。
4. `core/events.py` 追加事件类型（R1 对策）。
5. 新测试 3 个文件：编译成功路径 / 拒绝路径、依赖图构建、证伪记账。

**验收**：`pytest tests/unit/test_contract_assertion.py tests/unit/test_contract_compiler.py tests/unit/test_contract_ledger.py tests/unit/test_interfaces.py -v` 全绿，贴原始输出。

### 步骤 2 · T1.2 反向可达搜索 + 污染锥（M2 前半）

1. `causal.py`：`find_root_cause(falsified_aid) -> Assertion`（沿 `depends_on`/`derive` 反向 BFS/DFS，返回**最早**被证伪者，平局取路径最长/深度最大者）；`contamination_cone(root) -> set[aid]`（下游全部标记不可信）；`rerun_set(root) -> set[sub_id]`（需重跑的最小子图）。
2. 关键测试：≥5 步依赖链，第 2 步被证伪、第 5 步报错 → 必须返回第 2 步。

**验收**：`pytest tests/unit/test_contract_causal.py -v` 全绿，贴测试代码 + 原始输出。

### 步骤 3 · T1.3 类型驱动 dispatch 表 + 回归闸（M2 后半，核心创新）

1. `strategy_table.py` 新增 `TypedDispatch`：断言类型 → 动作，完整表：
   - pre+形状类（`is_type/has_keys`）→ `swap_adapter`；pre+值类（`in_range/match`）→ `re_observe`；pre+存在类（`not_empty`）→ `re_observe`，无路则 `halt`；post+未达标（`len/range`）→ `swap_skill`；post+形状类 → `re_assemble`；invariant 破 → `halt_escalate`。
   - 类型完备：`lookup_assertion(a: Assertion) -> RepairAction` 对任何 `(kind, predicate_class)` 组合都有唯一动作，无 fallback 格子。
2. `FixPlan` 扩展动作名（`swap_adapter/re_observe/halt_escalate`）；`swap_skill` 复用 FixPlan 的 `new_skills`，技能候选从注入的技能名清单取（R5 对策）。
3. `regression_gate.py`：修复后重跑此前已通过断言集合，任一 `verified→falsified` 则回滚装配并记 `REPAIR_ROLLED_BACK` 事件 + "有害修复"标记。
4. 测试：5 类型各一例 dispatch 正确 + 1 例"修 A 坏 B 被闸拦下回滚"。

**验收**：`pytest tests/unit/test_repair_dispatch.py tests/unit/test_repair.py -v` 全绿（旧测试原样通过），贴原始输出。

### 步骤 4 · T1.4 验证阶梯（M3）

1. `escalation.py`：维护每条断言的观测历史；连续 N（默认 3，可配）次稳定通过 → 尝试归纳静态规则（类型一致→类型断言、值域收敛→范围断言、同一正则→正则断言），归纳成功则 `L1→L2`；任何一次证伪 → 立即降回 L1。L3 首版只留数据结构位 + 人工设定入口，不做形式化验证（C 层 roadmap）。
2. 升级/降级各发一条 `ASSERTION_ESCALATED/DEGRADED` 事件（带 ts，R7 对策），`replay()` 可完整回放轨迹。
3. 不碰 `pool._tick_health`（T1.4 明确约束）；不动 `monitor/health.py`。
4. 测试：10 轮观测跑升级曲线 + 证伪回落。

**验收**：`pytest tests/unit/test_contract_escalation.py -v` 全绿，贴原始输出。
