现状的真实问题不是"没做过检索"，而是**技能来源这条路根本没有闸门**：

- `SkillPool.register()` 是公开方法，谁都能调；`skill_registry._try_register_real_skill()` 靠一张硬编码映射表把技能塞进池。**来源可信度、内容风险、版本兼容，一个都不检查。**
- 技能一旦来自第三方（pip 包 / GitHub 仓库 / 用户上传），**它本身就是不可信输入**——它是会被执行的指令，不是被动数据。

M5 解决"候选从哪来"，M4 解决"凭什么让它进来"。顺序上 **M4 必须先立**：没有闸门，发现层只是在扩大攻击面。

## 复用 vs 自造（按"能用现成的先用"）

### 直接复用
| 用途 | 现成的东西 | 怎么用的 |
|------|-----------|---------|
| 远程检索 | GitHub 官方 REST Search API | 走 `GET /search/repositories`，不自己爬页面。httpx（项目已有依赖） |
| 第三方技能发现 | Python 标准 `entry_points` 机制 | 兑现 `pyproject.toml` 里预留的那个 group，不自造插件协议 |
| 技能元数据格式 | Agent Skills 生态的 `SKILL.md` + YAML frontmatter | 解析 `name`/`description` 标量字段（不引 yaml 依赖，只认平面 key: value） |
| 危险模式编号 | Bandit 的 rule id 体系 | 直接沿用 B102/B301/B307/B506/B602/B603/B604/B105/B108/B310/B324/B322/B613，语义一致，**将来把 Bandit 当后端接进来时规则接口不用改** |
| 深度扫描后端 | `agentvet`（本仓库已有技能包） | `AgentVetBridge` 适配器，装了就走 L1，没装**如实记 `skipped: not installed`**（不假装扫过） |

### 自造（市面上确实没有）
**准入闸门**与**借还语义**的耦合。现成工具（Bandit / Semgrep / pip-audit）都是**报告工具**，没有"闸门"这个概念。三条具体差异：

| # | Bandit 的行为 | 本层的行为 | 为什么必须不一样 |
|---|--------------|-----------|----------------|
| 1 | 允许被扫对象写 `# nosec` 自我豁免 | **把豁免标记本身记成 HIGH**（rule HS-011） | 在准入语境里"技能作者 == 不可信方"。允许自我豁免 = 允许"加一行注释就关掉任意 CRITICAL 规则" |
| 2 | 扫完出报告，不拦谁注册 | `register_if_admitted()` 是唯一入口，非 ALLOW 直接 raise | 报告没人读等于没有。闸门要拦在**结构上**，不是拦在"程序员的自觉"上 |
| 3 | 扫描器崩了 → 没有报告 → 容易被读成"没问题" | **fail-closed**：规则异常/agentvet 异常 → 记 HIGH finding，verdict 不低于 QUARANTINE | "没扫到"和"没问题"是两件事，不能混 |

另有两项是本框架特有语义、必须自造的：
- **候选打分**：`Plan.subtasks[i].required_skills` 是硬信号，市面上没有这个输入形态。
- **候选 / 筛查 / 装配三段分离**：候选区里的东西"什么都不是"（还没验过任何东西），任何从 candidates 直接拿去跑的代码都是 bug。

## 接口约定

### M4
- `AdmissionSubject`（入参形态，不依赖 discovery 的类型）：name / trust / source_root / source_kind / remote_url / manifest / declared_api_version；`from_pack_dir()` 类方法
- `AdmissionRule`（ABC）：`rule_id` + `evaluate(subject, ctx) -> list[Finding]`
- `Finding`（frozen）：rule_id / severity / message / file / line / **evidence**（每条命中都必须带原文片段）
- `AdmissionGate`：`evaluate()` 纯判决 / `admit()` 判决+记账+发事件 / `register_if_admitted(pool, subject, factory)` 唯一注册入口 / `records()`
- `AdmissionReport`：verdict / trust / findings / **scanner_status** / files_scanned / **skipped**；`to_dict()` 可序列化
- 策略：`Severity × TrustLevel → Verdict` 表驱动，**取最严**（CRITICAL 不被 LOW 稀释）
- `SkillNotAdmittedError(RuntimeError)`：带完整 report
- `TrustLevel`：`FIRST_PARTY` / `SIGNED` / `UNVERIFIED`

### M5
- `SearchQuery`：intent / required_skills / tags
- `SkillCandidate`（frozen）：name / kind(`local_pack|pool|entry_point|github_repo`) / source / description / tags / trust / root / import_path / sys_path / remote_url / stars；`needs_fetch` 属性
- `SkillSource`（ABC）：`search(query) -> list[SkillCandidate]`，**只检索、不做准入判断**；查不到返回空列表**不抛**
- `SkillDiscovery`：`discover(intent, required_skills, tags)` → `DiscoveryResult` / `screen(cand)` → `ScreeningOutcome` / `install_selected(result, top_k)` / `to_subject(cand)`
- `DiscoveryResult`：candidates（全量候选+分数）/ **chosen（= 允许装配的全集，不裁剪）** / screened_out（附理由）/ source_status
- `build_default_discovery()`：本地源默认开，GitHub 源**默认关**（理由见下）

### EventType 追加 3 成员（**接口变更（字段枚举）**，向后兼容，只增不改）
`SKILL_DISCOVERED` / `SKILL_SCREENED` / `SKILL_ADMISSION_VERDICT`

## 实现要求
- 依赖方向单向：`discovery → admission → core.skill`。admission **不得** import discovery；两层都不得 import pool 的运行时对象（用 `TYPE_CHECKING`）
- 扫描有**规模上限**：单文件 512KB、单包 200 个文件、只扫文本类扩展名 —— 防"塞一个大文件把闸门拖死"这种低成本 DoS
- 扫描**边界**必须闭合：文件 `resolve()` 后仍须在包根目录内（POSIX 上防 symlink 逃逸）
- 打分**必须可解释**：每个候选带 score_breakdown，追问"为什么选它"能逐项答
- **装配前重判**（TOCTOU）：发现与装配之间可能隔着下载、人审、时间流逝，拿旧结论当放行凭证是漏洞
- 单源失败**不拖垮**整体发现；单个技能装不上不中断其余
- 事件发布失败**不得**影响判决结果

## 顺带修好的既有缺陷（3 个，都是实跑暴露的）

### ① `manifest.toml` 首行不是合法 TOML（3 个包）
`skills/{agentvet,ppt,web_search}_pack/manifest.toml` 第 1 行是 `"""Skill manifest — 描述技能包版本兼容性."""`——**TOML 没有这种语法**，`tomllib.load()` 直接在 line 1 column 3 报错。
一直没暴露的原因：`skill_registry.py` 用硬编码映射表，从来不读 manifest.toml。
**处置**：改成 TOML 注释 `# ...`。同时给解析器加一层**收得很紧**的容忍（只有"独占一行且整行仅一段三引号"才剥离），因为第三方包大概率也这么写。**真写坏的 manifest 依然会被 HS-001 报出来，不被容忍吞掉。**

### ② `ppt_pack/manifest.toml` 的 file 字段与实现不符
原写 `file = "ppt_pack/skills/collect.py:DataCollectSkill"` 等 4 处，但**实际 4 个类全在 `ppt_pack/skills.py` 单文件里**（`skills/` 子目录不存在）。按 manifest 去 import 必然失败。
**处置**：修正为 `ppt_pack/skills.py:<ClassName>`，并在 manifest 里留注释说明改动原因。

### ③ 准入规则误报真实第一方包
`crawler_pack` 被 HS-010 判 DENY，命中的是 `saved = os.environ.pop("NO_PROXY", None)` + `httpx.get(...)`——**设代理变量不是窃取凭据**。原规则里 `os\.environ` 这个 token 太宽泛。
**处置**：把"凭据来源"收紧成两种真信号：①敏感**文件**路径（`.ssh/` `id_rsa` `.aws/credentials` `.env` …）②名字里带凭据语义的**环境变量**（`environ["GITHUB_TOKEN"]`）。并补一条**防误报回归测试**，把这个案例钉住（`test_bare_os_environ_is_not_a_credential_source`）。

## 已知限制（交付时如实说明）
1. **远程候选找到也不等于能用**：M5 的 GitHub 源只产出"候选 + 留观"。要真用起来，需要人工取回本地 → 再过一次闸。这一步没自动化，是刻意的。
2. **准入层不是语言级强制**。Python 没有 friend 机制，`SkillPool.register()` 依然是 public 的。本层的强制方式是：唯一入口 + **静态检查测试**（新增绕过立刻红）。这是"工程约束"，不是"语言约束"——被问到要如实说。
3. **agentvet 未安装，深度扫描这条路本轮没实测过**。`AgentVetBridge.probe()` 实测走的是 `skipped: not installed` 分支；接入后的行为只有单元测试覆盖（注入假 engine），没有真实扫描验证。
4. **Windows 上测不出 symlink 逃逸**（实测：`symlink_to` 返回成功但生成的是哑链接，`rglob` 也不列出它）。该检查是给 POSIX 兜底的，在 Windows 上这条测试会 skip 并注明原因，不做假装通过。
5. **规则是正则级，不是 AST 级**。`exec(` 出现在字符串字面量里也会命中（宁可误报不可漏报）。要降到 AST 精度需要接 Bandit —— 那正是"复用"表里预留的位置。
